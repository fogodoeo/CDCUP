# 크레와트 시네마틱 선택 장면 제작 지침 v2

## 1. 목적

크레와트 질문 화면을 단순한 문답지가 아니라 한 장의 모의고사 삽화 안에서 두 가능성을 비교하고, 선택한 가능성 안으로 들어가는 짧은 체험으로 만든다.

핵심 경험은 다음과 같다.

> 왼쪽 가능성 · 중앙의 고민하는 나 · 오른쪽 가능성 → 선택 → 고른 장면만 확대되고 반대 장면은 검은 안개 속으로 사라짐

실제 동영상은 사용하지 않는다. 문항마다 정지 삽화 2장과 CSS 전환만 사용한다.

## 2. 문항별 기본 자산 구조

문항마다 가로 3:2 삽화 2장을 제작한다.

1. `choice`: 선택 전 비교 장면
   - 왼쪽 선택 가능성
   - 중앙에서 고민하는 주인공
   - 오른쪽 선택 가능성
2. `outcomes`: 선택 후 통합 결과 장면
   - 왼쪽 선택과 상호작용하는 주인공
   - 오른쪽 선택과 상호작용하는 주인공
   - 두 결과를 한 장에 모두 포함

선택 후 통합 결과 장면에는 동일한 주인공이 양쪽에 한 번씩 등장할 수 있다. 실제 화면에서는 고르지 않은 쪽을 즉시 검은 안개로 가리므로 두 인물이 동시에 노출되지 않게 한다.

기본 자산 수는 `12문항 × 2장 = 24장`이다. 별도 좌·우 결과 이미지나 공통 전경 인물을 추가하지 않는다.

## 3. 선택 전 화면 구성

선택 전 삽화는 하나의 캔버스 안에 세 개의 시각 구역을 둔다.

| 구역 | 권장 폭 | 내용 |
|---|---:|---|
| 왼쪽 | 32~34% | 선택지 A가 의미하는 상황 또는 대상 |
| 중앙 | 30~36% | 양쪽을 바라보며 고민하는 주인공 |
| 오른쪽 | 32~34% | 선택지 B가 의미하는 상황 또는 대상 |

### 구역 분리 방식

- 세 구역은 두꺼운 카드 테두리로 자르지 않는다.
- 각 구역에 `24~36px` 수준의 둥근 모서리를 사용한다.
- 경계는 1px 안팎의 옅은 연필선 또는 낮은 대비의 음영으로 처리한다.
- 구역 바깥쪽에는 20~40px 정도의 부드러운 페더링이나 종이 번짐을 허용한다.
- 세 구역 사이에는 캔버스 폭의 1.5~3% 정도 여백을 둔다.
- 전체 바탕의 종이 질감과 수평선은 이어지게 하여 한 장의 문제지처럼 보이게 한다.
- 각 구역이 서로 떨어져 보이되 모바일에서 세 장의 작은 썸네일처럼 보이지 않게 한다.

권장 시각 값:

```css
border-radius: 28px;
border: 1px solid rgba(53, 43, 32, .18);
box-shadow: 0 12px 28px rgba(37, 30, 24, .08);
```

### 중앙 주인공

- 성인 남성 또는 여성 한 명을 자연스러운 뒷모습이나 3/4 뒷모습으로 배치한다.
- 주인공은 왼쪽과 오른쪽을 모두 의식하는 자세여야 한다.
- 손으로 작은 물건을 잡거나 화면을 들여다보게 하지 않는다.
- 과장된 고민 포즈, 머리를 감싸는 동작, 만화식 물음표를 사용하지 않는다.
- 주인공이 양쪽 선택 장면을 가리지 않게 한다.

## 4. 선택 전 장면 설계 원칙

- 좌우 상황은 같은 크기, 밝기, 정보량으로 만든다.
- 어느 한쪽도 더 좋은 답이나 정답처럼 보이지 않게 한다.
- 선택지 문장을 그대로 사물로 번역하기 어려우면 해당 문항이 측정하는 차이를 공간과 관계로 표현한다.
- 사진, 휴대폰, 기록지처럼 생성 오류가 잦은 물건을 억지로 넣지 않는다.
- 한 구역의 핵심 대상은 1~2개로 제한한다.
- 좌우 핵심 대상은 각 구역 중앙 안전 영역에 둔다.
- 중앙 인물과 좌우 대상 사이에 시선 또는 동선이 자연스럽게 이어져야 한다.

예시:

- 대화와 혼자 정리: 왼쪽은 열린 대화 공간, 오른쪽은 조용한 개인 관찰 공간
- 현재와 가능성: 왼쪽은 지금의 개체 표현, 오른쪽은 가족·성장 흐름을 암시하는 구성
- 계획과 유연성: 왼쪽은 완성된 환경, 오른쪽은 조정 가능한 기본 환경

## 5. 선택 후 통합 결과 장면

`outcomes` 이미지는 왼쪽과 오른쪽 결과를 한 장에 함께 제작한다.

- 왼쪽 절반에는 주인공이 왼쪽 선택 대상과 실제로 상호작용하는 장면을 둔다.
- 오른쪽 절반에는 동일한 주인공이 오른쪽 선택 대상과 실제로 상호작용하는 장면을 둔다.
- 두 결과의 공간 재질, 카메라 높이, 조명과 주인공 외형을 일치시킨다.
- 중앙 8~12%는 안개 그라데이션이 겹치는 완충 영역으로 둔다.
- 양쪽 핵심 대상은 각각 자기 절반의 중앙에 둔다.
- 반대편 안개가 덮여도 선택한 장면의 얼굴, 크레, 사육장과 행동이 잘리지 않게 한다.
- 결과 이미지가 화면에 나타나는 첫 프레임부터 반대쪽 안개도 함께 표시한다. 동일 인물 두 명이 동시에 보이는 순간을 만들지 않는다.

이 구조의 목적은 좌·우 결과 이미지를 따로 생성하지 않고도 두 선택의 상호작용을 모두 보유하는 것이다.

## 6. 선택 후 확대와 검은 안개

### 선택한 쪽

- 왼쪽 선택 시 확대 원점은 가로 25%, 오른쪽 선택 시 75%로 둔다.
- 결과 이미지를 약 `1.12~1.18배` 확대한다.
- 선택한 구역이 화면 중앙으로 6~12% 이동하도록 한다.
- 확대는 420~650ms 동안 부드럽게 안정시킨다.
- 확대 후에도 핵심 대상 전체가 보여야 한다.

### 선택하지 않은 쪽

- 평평한 검은 사각형 대신 먹색 안개 그라데이션을 사용한다.
- 바깥쪽은 88~96% 불투명, 중앙 접점은 68~82% 불투명으로 처리한다.
- 약한 블러와 종이 입자 질감을 넣어 삽화에 자연스럽게 섞이게 한다.
- 선택하지 않은 결과의 인물과 핵심 행동은 식별되지 않을 정도로 가린다.
- 선택한 구역까지 검게 번지지 않게 중앙 경계를 관리한다.

권장 예시:

```css
background:
  linear-gradient(90deg, rgba(12, 11, 12, .96), rgba(18, 16, 18, .84) 72%, transparent),
  repeating-linear-gradient(92deg, rgba(255,255,255,.025) 0 2px, rgba(0,0,0,.025) 2px 14px);
backdrop-filter: blur(9px) saturate(.45) brightness(.62);
```

완전한 순검정은 사용하지 않는다. 모의고사 삽화의 선이 희미하게 남는 먹색 안개를 목표로 한다.

## 7. 선택 애니메이션 타임라인

한 번의 선택 연출은 약 850~950ms로 구성한다.

| 시간 | 연출 |
|---|---|
| 0ms | 선택 입력, 버튼 잠금 |
| 0~160ms | 선택 전 이미지가 선택 방향으로 1.03배 이동 |
| 140~360ms | `choice`에서 `outcomes`로 교차 전환 |
| 140~360ms | 선택하지 않은 쪽의 검은 안개 동시 등장 |
| 300~650ms | 선택한 결과를 1.12~1.18배 확대하고 중앙 쪽으로 이동 |
| 650~900ms | 장면 안정, 다음 문항 전환 |

모션 감소 환경에서는 150ms 이내 교차 전환과 안개 표시만 적용한다.

## 8. 선택지 좌우 무작위화

문장 순서를 무작위로 바꾸더라도 이미지 자체를 매번 좌우 반전하지 않는다.

- 결과 이미지의 왼쪽과 오른쪽 의미를 데이터로 고정한다.
- 각 답이 어느 결과 구역에 연결되는지 `outcomeSide`로 관리한다.
- 화면에서 선택지 위치가 바뀌면 버튼과 `outcomeSide`의 연결만 바꾼다.
- 크레의 몸과 공간 전체를 좌우 반전해 생기는 시각적 점프를 피한다.

예시:

```js
{
  C01: {
    choice: 'question-c01-choice-v2.webp',
    outcomes: 'question-c01-outcomes-v2.webp',
    outcomeByLetter: { E: 'left', I: 'right' }
  }
}
```

## 9. 인물 일관성

- 한 문항의 `choice`와 `outcomes`에서 같은 인물로 보여야 한다.
- 머리 모양, 옷, 체형, 키와 시점 높이를 고정한다.
- 결과 이미지 양쪽에 등장하는 인물도 동일 인물이어야 한다.
- 문항마다 남성과 여성을 교차 사용할 수 있지만 한 문항 안에서는 바꾸지 않는다.
- 성별을 과장하는 의상, 체형과 액세서리를 피한다.
- 손가락이 복잡한 조작은 피하고, 큰 대상과 자연스럽게 상호작용하게 한다.

## 10. 크레스티드게코 종 고증

모든 크레는 `Correlophus ciliatus`로 즉시 알아볼 수 있어야 한다.

- 넓은 삼각형 머리
- 매우 큰 눈과 눈꺼풀이 없는 형태
- 눈 위에서 등 양쪽으로 이어지는 속눈썹 같은 볏
- 네 개의 다리
- 접착 패드가 보이는 발가락
- 적당히 굵은 잡는꼬리
- 나뭇가지를 붙잡는 자연스러운 수목성 자세

추가 다리, 중복 꼬리, 비정상적인 발가락이나 다른 도마뱀 종 형태가 보이면 폐기한다.

## 11. 금지 요소와 단순화 규칙

원칙적으로 사용하지 않는다.

- 휴대폰, 태블릿, 노트북, 모니터
- 사진, 엽서, 기록지, 체크리스트와 달력
- 읽을 수 있는 글자, 숫자, 로고
- 화면 속 화면
- 작은 물건을 잡거나 조작하는 복잡한 손
- 마법학교, 로브, 고딕 건축과 판타지 장식
- 한 구역에 3개가 넘는 설명용 오브젝트
- 선택지마다 전혀 다른 방처럼 보이는 배경

정보는 물건의 개수보다 주인공의 위치, 시선, 거리, 공간의 개방감과 상호작용으로 표현한다.

## 12. 공통 이미지 생성 스타일

모든 프롬프트에 다음 조건을 포함한다.

```text
현대의 현실적인 크레스티드게코 사육 또는 행사 공간.
한국 모의고사 문제지의 세련된 흑백 삽화풍.
섬세한 연필·잉크 선, 절제된 옅은 회색 명암과 따뜻한 아이보리 종이 질감.
가로 3:2, 하나의 자연스러운 시점과 수평선.
둥근 모서리와 희미한 연필선 경계로 장면 구역이 부드럽게 분리됨.
글자, 숫자, 로고, 휴대폰, 사진, 종이 기록지와 판타지 요소를 넣지 말 것.
크레스티드게코는 실제 Correlophus ciliatus의 머리, 볏, 눈, 발가락 패드와 꼬리를 정확히 표현할 것.
과도한 소품과 설명용 오브젝트를 넣지 말 것.
```

### `choice` 프롬프트 추가 조건

```text
한 화면을 왼쪽 선택 가능성, 중앙의 고민하는 주인공, 오른쪽 선택 가능성으로 구성.
세 구역의 크기와 밝기는 동등하며 어느 한쪽도 정답처럼 보이지 않음.
각 구역은 둥근 모서리, 옅은 연필선과 부드러운 페더링으로 분리.
주인공은 양쪽을 모두 의식하는 자연스러운 뒷모습 또는 3/4 뒷모습.
```

### `outcomes` 프롬프트 추가 조건

```text
왼쪽 절반에는 왼쪽 결과와 상호작용하는 주인공, 오른쪽 절반에는 오른쪽 결과와 상호작용하는 동일 주인공.
양쪽 결과를 한 장에 모두 포함하되 각각 자기 절반의 안전 영역 안에서 완결됨.
중앙 8~12%는 검은 안개가 겹칠 완충 영역으로 비움.
검은 안개와 확대 효과는 이미지에 직접 그리지 않고 웹 CSS로 처리.
```

## 13. 반응형 규칙

- 이미지 내부 좌표계는 항상 3:2로 유지한다.
- 기본은 `object-fit: contain`을 사용한다.
- 320px에서도 좌·중앙·우 세 구역의 의미가 구분돼야 한다.
- 모바일에서는 선택지 버튼을 이미지 아래에 두되 각 버튼 색이나 A/B 표식이 해당 이미지 구역과 연결되어 보이게 한다.
- 결과 확대 시 선택한 핵심 대상이 화면 밖으로 잘리지 않게 한다.
- 320px, 375px, 390px, 768px와 1280px 이상에서 검수한다.

## 14. 성능과 로딩

- 최종 파일은 WebP 또는 AVIF로 저장한다.
- 1536×1024 기준 장당 250~500KB를 목표로 한다.
- 현재 문항의 `choice`, `outcomes` 2장과 다음 문항의 `choice` 1장만 미리 불러온다.
- `outcomes` 디코딩이 끝난 뒤 선택 입력을 받는 것이 가장 안전하다.
- 삽화 세트가 바뀌면 캐시 키도 변경한다.

## 15. 접근성

- 삽화는 보조 수단이며 선택지 문장만으로도 답할 수 있어야 한다.
- 선택 전 대체 텍스트는 두 가능성을 한 문장으로 요약한다.
- 결과 이미지와 검은 안개는 장식 요소로 처리한다.
- 색과 밝기만으로 선택 상태를 전달하지 않고 버튼의 `aria-pressed`도 함께 갱신한다.
- `prefers-reduced-motion: reduce`에서 확대와 이동을 제거한다.

## 16. 문항별 제작 절차

1. 두 선택의 차이를 한 문장으로 정의한다.
2. 좌우 각 구역의 핵심 대상 또는 관계를 하나씩 정한다.
3. 중앙 고민 인물을 포함한 `choice` 이미지를 제작한다.
4. 같은 공간·인물로 양쪽 상호작용을 담은 `outcomes` 이미지를 제작한다.
5. 양쪽 결과가 각각 절반 화면에서 완결되는지 확인한다.
6. 선택 즉시 반대쪽 안개가 표시돼 두 인물이 동시에 보이지 않는지 확인한다.
7. 왼쪽과 오른쪽을 각각 확대해 핵심 대상이 잘리지 않는지 확인한다.
8. 크레 종 형태와 사람의 손·관절을 확대 검수한다.
9. 좌우 선택지 순서를 바꿔도 `outcomeSide` 연결이 정확한지 확인한다.
10. 모바일과 데스크톱에서 전환을 실행한다.

## 17. 최종 검수표

### 선택 전

- [ ] 왼쪽 선택 · 중앙 고민 인물 · 오른쪽 선택이 즉시 구분된다.
- [ ] 세 구역이 둥글고 희미한 경계로 분리된다.
- [ ] 좌우 크기, 밝기와 정보량이 비슷하다.
- [ ] 과도한 설명용 오브젝트가 없다.

### 선택 후

- [ ] 양쪽 상호작용 결과가 한 이미지에 모두 존재한다.
- [ ] 선택하지 않은 쪽은 먹색 안개로 식별되지 않게 가려진다.
- [ ] 선택한 쪽은 자연스럽게 확대되고 중앙으로 이동한다.
- [ ] 동일 인물 두 명이 동시에 노출되는 프레임이 없다.
- [ ] 선택한 장면의 크레, 인물과 핵심 행동이 잘리지 않는다.

### 품질과 기능

- [ ] `choice`와 `outcomes`의 인물·방·조명이 일치한다.
- [ ] 실제 크레스티드게코로 보이며 신체 오류가 없다.
- [ ] 좌우 무작위화 뒤에도 문장과 결과 구역이 일치한다.
- [ ] 아이폰 터치 후 다음 문항에 호버나 선택 상태가 남지 않는다.
- [ ] 320px에서도 가로 넘침이 없다.
- [ ] 모션 감소 설정에서도 선택 결과를 알 수 있다.

## 18. 완료 기준

한 문항은 다음을 모두 만족해야 완료로 본다.

- `choice`, `outcomes` 두 이미지 검수 완료
- 선택 전 세 구역의 균형 통과
- 좌·우 결과 확대와 검은 안개 전환 통과
- 인물과 크레 고증 통과
- 선택지 무작위화 매핑 통과
- 모바일·데스크톱·모션 감소 환경 검수 완료
- 이미지 압축과 캐시 키 반영 완료
